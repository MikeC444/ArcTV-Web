# Developer panel (web)

`/admin`, linked from Settings → Account for accounts the backend flags as admins (`users.is_admin`, set by hand in the database; see the backend's
`docs/ADMIN.md`). Read-only: a summary (users, activity, plans, a **live user-growth chart**), a user list you can filter by email or name, plan, app version, has addons, has Continue Watching and last seen (a filter row under the column headings, "Clear filters" to reset; the filtering is done on the server so it covers every user, not only the rows shown), and per user the devices
with their app version, profiles, addons (host and debrid service only, never the key; under each, small pills for what its manifest offers in the apps' terms (about how many Home rows its catalogues make, details, sources, subtitles) and amber pills, with the full explanation on hover, for catalogues of a type the apps ignore (anything but movie and series, such as anime) or title ids that are not IMDb's (such as kitsu:), which may not open or play; needs the backend's `capabilities` on each addon, left out without it), Continue Watching and recent history. It refreshes itself every
30 seconds, so a device that updates its app shows the new version without a reload.

* **User growth** (under the summary cards): a live line chart of how many accounts exist, one point per day for up to 180 days from the summary's `userGrowth` (UTC days; deleted accounts are counted on no day). Range buttons show 7 / 30 / 90 days or all of it, starting at the first sign-up; hover or the arrow keys read any day (total, new that day), and "View as table" lists the same numbers. It redraws with the panel's 30-second refresh. Hidden on a backend that doesn't send `userGrowth` (the server has to be redeployed first).
* **Web users by system** (below the growth chart): how many people use the website on Windows, macOS, Android, iOS, Linux, ChromeOS or something unknown, as bars with a count and share. Signed-in browsers only (not the Fire TV or phone apps); the system is read from the browser name saved at sign-in, so a browser that hides it counts as Other. Pressing a bar filters the users list to those people (pressing it again clears it). Needs the backend's `webSystems` and the `webSystem` user filter; without them the card is left out. Code: `WebSystems.tsx`, `lib/webSystems.ts`.
* **Playback health** (above Other players): how viewings of the last 7 days ended, from reports the Fire TV and phone apps send when a viewing ends. It shows the share that were left early (under 30 seconds after the picture appeared, a player error, or nothing ever appeared), the median time to the first picture and how often it was not the first source tried, then splits by device model, player (VLC or built-in) and quality; a group with at least 10 viewings and clearly more early exits than the overall rate gets an amber outline. No titles, content ids or stream addresses are recorded. Needs the backend's `playback` summary and app versions that send the reports; without them the card says no reports yet or is left out. Code: `PlaybackHealth.tsx`, `lib/playbackHealth.ts`.
* **Downloads** (below Playback health): web Download use in the last 7 days, from small reports the web app sends when someone presses a Download button without Plus (the Plus popup is shown), opens the Downloads panel, or presses a file in it. It shows how many people tried, how many saw the Plus popup, how many opened the panel, and how many pressed a file ("started a download", with its share of those who opened the panel), plus the share that were episodes or not cached and a split by quality. A pressed file is the most the web app can know: the browser does the download, so a cancelled or failed one still counts; the phone and Mac apps do not report yet. No titles, content ids, release names or file addresses are recorded. Needs the backend's `downloads` summary (migration 0031) and a web build that sends the reports; without them the card is left out or says nothing yet. Code: `DownloadStats.tsx`, `lib/downloadStats.ts`, `state/downloadEvents.ts`.
* **Other players** (below the growth chart; one Minimise / Expand button folds the numbers and the hand-off list together, remembered in this browser only): from the summary's `externalPlayer`, how often titles were opened in another app or VLC's engine in the last 7 days (and all-time app opens), how many people, how many came after a playback error vs. the button vs. no player installed, and the 50 most recent hand-offs (title, source quality, which engine, trigger, person, error, app version). Hidden on a backend that doesn't send it.
* The old "App versions in use" chips are gone; the version filter in the user list (and the old-version marks on each device) still use the same data.
* Positions in a user's Continue Watching / Recently watched show seconds under a minute ("45s", "0s") and minutes after.
* "Recently watched" leaves out rows that never got anywhere (an episode marked as not watched, or one opened and left at 0s) and folds finished episodes of one season within ten minutes of each other into one line ("Ted Lasso S2 · 12 episodes finished (E1–E12)"), so marking a season watched is one row, not twelve.
* The X beside "Most recent hand-offs" hides that list in this browser (a "Show" button brings it back); nothing is deleted.
* The web server proxies three GET paths only (`server/src/routes/admin.ts`: `/api/admin/summary`, `/users`, `/users/:id`) with the sealed-cookie bearer;
  the backend does the admin check and answers everyone else with 404, and the page shows "Page not found" to non-admins.
* `GET /api/auth/session` now includes `isAdmin`; the web server sends `X-ArcTV-App-Version: web` so web sessions show as "Web" in the panel.
* **Download (Plus members and developer accounts; on the web and in the Mac app):** a Download button on a title's details page, beside Play and Trailer (for a show it says Download S1E1 and uses the episode the Play button would play). It opens a popup like the right-click menu (the title's backdrop picture across the top with its logo and year over it, "Downloads" with a back arrow and a close button on the picture, the ArcTV logo above); it never grows past the window, so the banner stays put and only the list scrolls, that looks up the sources and lists the ones that are a plain https link to one video file (not HLS / DASH streams, torrent-only or YouTube sources, sources that need request headers, or http links), sorted automatically (there is no sort or filter control): highest quality first and, within a quality, the smallest file first, with files the debrid service has already stored above ones it still has to fetch, and camera recordings last. Each row shows the quality, what kind of release it is (UHD Blu-ray REMUX, 4K WEB-DL, Blu-ray...), the file name, size, codec, an HDR or Dolby Vision tag and whether it is cached, and is an ordinary link: the browser downloads the file straight from the debrid service, nothing passes through this server (the links are separate clicks because a download started after the lookup would be blocked as a pop-up). Who sees it is decided in `Detail.tsx` (`useHasPlus()` or `user.isAdmin`; everyone counts as Plus while Plus is in early access), and it is listed in the Plus perks in `domain/plus.ts`; `lib/download.ts` and `state/downloadSources.ts` decide which sources qualify. Recorded in `docs/PARITY.md` (web and Mac, not the Firestick or phone).
