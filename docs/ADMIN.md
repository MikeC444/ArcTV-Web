# Developer panel (web)

**The dashboard (`/admin`, `/admin/<view>`, `/admin/users/<id>`).** It fills the screen with its own left rail (no site navigation): **Overview**, **Watching**, **Users**, **Downloads**, **Addons**, **Versions** and **Crashes** (keys 1 to 7 jump between them; Ctrl+K or `/` opens a search that finds any account by email or name, or jumps to a view; the arrow on the top bar goes back to Arc TV). A live strip on the top bar shows who is online (pressing it opens Users) and watching, and everything refreshes every 30 seconds. Each view has its own address, so a view or a person can be linked to.

* **Overview** fits one laptop screen (it scrolls on a short or narrow one): Users (with a 30-day trend), Active this week (with today and 30 days when the backend sends `activity`), New this week (daily bars and the change on last week), Plus (a bar of monthly / yearly / lifetime), a live donut of who is online by app, the growth chart, devices by app, a downloads funnel, and **Needs attention**. Tiles open their view.
* **Needs attention** is a set of rules over numbers the panel already has (`lib/dash.ts`, `attentionAlerts`), recalculated on every refresh, so an alert exists only while its rule holds: a viewing group (device, player or quality) people leave early much more than the rest, 40%+ of all viewings ending early, a fifth or more of devices behind their own app's newest version, a sign-up day at least 3x the usual (and 5+), few people pressing a file after opening Downloads, and people whose addon only has catalogues the apps ignore. Worst first, and "Nothing needs attention" when nothing holds. It cannot see crashes (the apps do not report them), only viewings that ended early.
* **Watching** lists who is watching right now: one card per device that saved playback progress in the last 45 seconds (the apps save about every 15 s while playing), newest first, with the title (and season / episode), how far in, which app and version, the profile and the person; pressing a card opens that person in Users. It refreshes every 10 seconds, and the "watching" pill on the top bar opens it. The title comes from the person's Continue Watching row saved closest to that moment, so it says "Title not known" rather than guess when there is none close enough (for example a title finished a moment ago). Needs the backend's `GET /admin/watching`; the proxy allows that path too.
* **Users** is a list (avatar with an online dot, plan, devices with old versions in amber, addons, Continue Watching, last seen) with search, a version filter, a Continue Watching filter and one-click groups (Everyone, Online now, Active this week, Free, Monthly, Yearly, Lifetime, No addons, Gone quiet). Pressing a person opens a side panel with Profile, Devices, Addons (with the same offer pills and amber notes as before) and Watching tabs, instead of expanding in place. The filtering is still done on the server.
* **Downloads** explains itself in words: pressing Download on the web app either shows the Plus popup (no Plus) or opens the file list (Plus), and pressing a file is the last thing we can see. Four tiles (Pressed Download, Stopped by the Plus popup, Opened the file list, Pressed a file) each carry a sentence saying what they count, then a day-by-day chart of the three actions, movies against shows, cached against not, the quality of the files pressed, **Who is trying** (every person from the last 7 days with their plan, how far they got, how many popups / lists / files and the quality they pressed most, filterable by Pressed a file / Opened the list only / Stopped by the Plus popup; pressing a row opens them in Users), **Latest activity** (the last 60 events in plain words, e.g. "Pressed a 4K file for an episode (cached)") and Other players. The per-day and per-person parts need the backend's `GET /admin/downloads`; the tiles work without it. Still no titles, content ids, release names or file addresses are recorded. The Overview tile is the same four numbers, counted in people.
* **App popups** and **Playback** were removed as views (Oct 2026). The Overview keeps one tile from them, **Viewings · 7 days** (how many times people pressed play on any app in the last 7 days, and how many people), from the summary's `playback`. The "Needs attention" list no longer has playback alerts. The web app still reports its app popup events; the panel no longer shows them.
* **Crashes** lists what the apps report after closing unexpectedly (the Fire TV app sends it the next time it opens: an uncaught error, and on Android 11+ a native crash, a freeze or being closed for memory while on screen). It groups the last 30 days by problem (how often, how many people, which versions and devices, the latest trace) and lists the latest 100 reports with their full trace and the person, when they were signed in. Nothing is emailed. Needs the backend's `GET /admin/crashes`; the proxy allows that path too.
* **Versions** keeps what its card used to show. **Versions** now compares each app with its **own** newest version (the old panel compared with the newest number anywhere), lists every version per app with its devices, and pressing one lists those people; the website's systems are there too.
* **Addons** (needs the backend's `addons` summary): people with addons and with a debrid service, people with an addon that returns nothing, the most-installed addon sites (with ignored catalogue types and non-IMDb id prefixes), and debrid services. Without it the view says it needs the newer backend.
* Code: `ui/dash/` (one file per view, `Primitives.tsx` for the tiles and charts), `lib/dash.ts` (version adoption, the attention rules, chart shapes), `styles/dash.css`. The proxy allows the same three GET paths as before.

The notes below describe each part in detail; where they mention the old long page or the filter row, the dashboard above is the current layout.

`/admin`, linked from Settings → Account for accounts the backend flags as admins (`users.is_admin`, set by hand in the database; see the backend's
`docs/ADMIN.md`). Read-only: a summary (users, activity, plans, a **live user-growth chart**), a user list you can filter by email or name, plan, app version, has addons, has Continue Watching and last seen (a filter row under the column headings, "Clear filters" to reset; the filtering is done on the server so it covers every user, not only the rows shown), and per user the devices
with their app version, profiles, addons (host and debrid service only, never the key; under each, small pills for what its manifest offers in the apps' terms (about how many Home rows its catalogues make, details, sources, subtitles) and amber pills, with the full explanation on hover, for catalogues of a type the apps ignore (anything but movie and series, such as anime) or title ids that are not IMDb's (such as kitsu:), which may not open or play; needs the backend's `capabilities` on each addon, left out without it), Continue Watching and recent history. It refreshes itself every
30 seconds, so a device that updates its app shows the new version without a reload.

* **User growth** (under the summary cards): a live line chart of how many accounts exist, one point per day for up to 180 days from the summary's `userGrowth` (UTC days; deleted accounts are counted on no day). Range buttons show 7 / 30 / 90 days or all of it, starting at the first sign-up; hover or the arrow keys read any day (total, new that day), and "View as table" lists the same numbers. It redraws with the panel's 30-second refresh. Hidden on a backend that doesn't send `userGrowth` (the server has to be redeployed first).
* **Web users by system** (below the growth chart): how many people use the website on Windows, macOS, Android, iOS, Linux, ChromeOS or something unknown, as bars with a count and share. Signed-in browsers only (not the Fire TV or phone apps); the system is read from the browser name saved at sign-in, so a browser that hides it counts as Other. Pressing a bar filters the users list to those people (pressing it again clears it). Needs the backend's `webSystems` and the `webSystem` user filter; without them the card is left out. Code: `WebSystems.tsx`, `lib/webSystems.ts`.
* **Downloads**: web Download use in the last 7 days, from small reports the web app sends when someone presses a Download button without Plus (the Plus popup is shown), opens the Downloads panel, or presses a file in it. It shows how many people tried, how many saw the Plus popup, how many opened the panel, and how many pressed a file ("started a download", with its share of those who opened the panel), plus the share that were episodes or not cached and a split by quality. A pressed file is the most the web app can know: the browser does the download, so a cancelled or failed one still counts; the phone and Mac apps do not report yet, and the Windows app sends the same three reports, so its use is counted in the same numbers (there is no split by app). No titles, content ids, release names or file addresses are recorded. Needs the backend's `downloads` summary (migration 0031) and a web build that sends the reports; without them the card is left out or says nothing yet. Code: `DownloadStats.tsx`, `lib/downloadStats.ts`, `state/downloadEvents.ts`.
* **Other players** (below the growth chart; one Minimise / Expand button folds the numbers and the hand-off list together, remembered in this browser only): from the summary's `externalPlayer`, how often titles were opened in another app or VLC's engine in the last 7 days (and all-time app opens), how many people, how many came after a playback error vs. the button vs. no player installed, and the 50 most recent hand-offs (title, source quality, which engine, trigger, person, error, app version). Hidden on a backend that doesn't send it.
* The old "App versions in use" chips are gone; the version filter in the user list (and the old-version marks on each device) still use the same data.
* Positions in a user's Continue Watching / Recently watched show seconds under a minute ("45s", "0s") and minutes after.
* "Recently watched" leaves out rows that never got anywhere (an episode marked as not watched, or one opened and left at 0s) and folds finished episodes of one season within ten minutes of each other into one line ("Ted Lasso S2 · 12 episodes finished (E1–E12)"), so marking a season watched is one row, not twelve.
* The X beside "Most recent hand-offs" hides that list in this browser (a "Show" button brings it back); nothing is deleted.
* The web server proxies three GET paths only (`server/src/routes/admin.ts`: `/api/admin/summary`, `/users`, `/users/:id`) with the sealed-cookie bearer;
  the backend does the admin check and answers everyone else with 404, and the page shows "Page not found" to non-admins.
* `GET /api/auth/session` now includes `isAdmin`; the web server sends `X-ArcTV-App-Version: web` so web sessions show as "Web" in the panel.
* **Download (Plus members and developer accounts; on the web and in the Mac app):** a Download button on a title's details page, beside Play and Trailer (for a show it says Download S1E1 and uses the episode the Play button would play). It opens a popup like the right-click menu (the title's backdrop picture across the top with its logo and year over it, "Downloads" with a back arrow and a close button on the picture, the ArcTV logo above); it never grows past the window, so the banner stays put and only the list scrolls, that looks up the sources and lists the ones that are a plain https link to one video file (not HLS / DASH streams, torrent-only or YouTube sources, sources that need request headers, or http links), sorted automatically (there is no sort or filter control): highest quality first and, within a quality, the smallest file first, with files the debrid service has already stored above ones it still has to fetch, and camera recordings last. Each row shows the quality, what kind of release it is (UHD Blu-ray REMUX, 4K WEB-DL, Blu-ray...), the file name, size, codec, an HDR or Dolby Vision tag and whether it is cached, and is an ordinary link: the browser downloads the file straight from the debrid service, nothing passes through this server (the links are separate clicks because a download started after the lookup would be blocked as a pop-up). Who sees it is decided in `Detail.tsx` (`useHasPlus()` or `user.isAdmin`; everyone counts as Plus while Plus is in early access), and it is listed in the Plus perks in `domain/plus.ts`; `lib/download.ts` and `state/downloadSources.ts` decide which sources qualify. Recorded in `docs/PARITY.md` (web and Mac, not the Firestick or phone).
